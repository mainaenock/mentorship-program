# Decisions

1. Empty repository baseline: only a 20-byte README; no prior app, package manager, tests, or failures. Git status had no unrelated changes. Retain repository identity and use pnpm.
2. Official `create-vinext-app` Cloudflare scaffold, generated in a temporary subfolder because the existing README prevented in-place scaffolding. Scaffold files moved into root, original README then expanded.
3. Next.js 16.3.5 and React 19.3.0 API surface, vinext 1.0.0-beta.9, Vite 8.3.0, Workers plugin. Versions pinned after installation. See [vinext documentation](https://github.com/cloudflare/vinext) for limitations. Vinext is beta, not guaranteed full Next.js parity. Static check reports 100% supported for currently used APIs.
4. Tailwind 4 plus semantic CSS variables: cream/teal, serif editorial headings, readable sans-serif forms, light/dark themes, reduced motion, 360px baseline. Visual journey uses CSS/SVG, no unverifiable imagery or member claims.
5. Radix primitives provide focus management for dialogs, drawers, tabs, dropdowns, tooltips. Native form controls provide keyboard/mobile behaviour. React Hook Form + Zod validate credentials. Client libraries have no Node-only runtime requirement. Tests/build will verify integration, rather than assuming package compatibility.
6. No TanStack Query: there is no production client server-state cache to manage yet. Service interfaces preserve replacement boundaries. No Express server.
7. Explicit demo mode: auth and contact/consent/application operations simulate outcomes without sending or uploading anything. Session storage is not production authentication. Passwords are not persisted. Production provider integration is a release prerequisite.
8. No fabricated prices, statistics, partners, stories, or team members. Zero registration is a seed configuration, other commercial terms await approval. Legal documents are marked draft. Contact routes replace unconfigured contact addresses.
9. PWA caches only four public fallback/icon assets. Navigation is network-first without response caching. Account, financial, consent, and application data never enter Cache Storage. Update prompt requires user action to avoid losing form progress.
10. Storybook is optional and deferred: shared primitives/composites are source-documented and covered by RTL; adding a second Vite/RSC development graph is not needed to validate this foundation. Add isolated Storybook configuration in a future design-system maintenance task.
11. Public content shares an explicit allowlisted catch-all route; domains remain separate. Unknown paths invoke not-found. Future authenticated routes should have separate server-enforced layouts once the backend exists.
12. Kenya defaults remain centralised. Adult threshold is a configurable product default, subject to legal review for target jurisdictions. No legal conformance claim is made by the templates.
13. TypeScript is pinned to 6.0.3. The scaffold selected 7.0.2, but the installed typescript-eslint parser explicitly rejects TypeScript 7. TypeScript 6 preserves strict mode and supports the selected framework.
14. All forms use `SafeForm`: disabled fieldset until hydration, POST fallback, and a no-JavaScript explanation. Shared buttons/inputs and mobile navigation are also inert until ready. Browser testing found that a pre-hydration submit could otherwise put demo credentials into a GET URL; the regression test now checks the server-rendered form with JavaScript disabled.
15. Set Workers assets `html_handling` to `none`. The default redirects `/offline.html` to `/offline`, which would cache the dynamic page instead of the deliberately static fallback. PWA tests inspect the exact cache keys and then navigate offline.
16. Mentor status fixtures live behind `MentorService.status`, including more-information requests and a resubmission action. They cannot grant real mentor roles. Guardian withdrawal uses its own service contract and is shown only after an affirmative demo consent choice.
17. On Windows, stop the running built Worker before rebuilding: it can hold `dist` open. Browser validation uses the production Worker at port 4173, with installed Chrome as an alternative when Playwright's Chromium download is unavailable.
