# API contract — proposed production boundary

## Prompt 2 typed boundaries

The following interfaces are implemented by isolated tab-local demo adapters. Production responses must enforce ownership, assignment, linked-child scope and granular staff grants before returning data. Client guards are UX only.

| Interface                                                            | Production endpoint family                                                                                                                                            | Critical invariants                                                                                                                                                                          |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GoalService` (`domains/goals/contracts.ts`)                         | `/api/goals`, `/api/goals/:id/actions`, `/occurrences/:id`, `/evidence`, `/evaluations`, `/interventions`                                                             | Owner scope, version conflict detection, weighted milestones, exact completion undo, immutable evaluation snapshots, archived read-only history                                              |
| `LearningService` (`domains/learning/contracts.ts`)                  | `/api/learning`, `/api/my-learning/:id`, `/quiz`, `/attachments`, `/purchases`, `/certificate`                                                                        | Entitlement checked before lesson/quiz access; idempotent credit debit; certificate eligibility; private download authorization                                                              |
| `PaymentService` (`domains/payments/contracts.ts`)                   | `/api/credits`, `/api/payments`, `/api/payments/:id/checkout`, `/status`, `/refund-request`, `/receipt`                                                               | Integer minor units; trusted provider settlement only; auditable ledger; no credits from redirects; refund request is not settlement                                                         |
| `AccountService` (`domains/account/service.ts`)                      | `/api/profile`, `/api/preferences`, `/api/notifications`, `/api/account/requests`                                                                                     | Self scope; verified contact changes need independent verification; privacy requests require identity checks before fulfillment                                                              |
| `MentorshipPortalService` (`domains/mentorship/portal-contracts.ts`) | `/api/mentorship/assignment`, `/api/mentor/mentees/:id`, `/api/sessions`, `/api/messages`, `/api/mentor/notes`, `/recommendations`, `/interventions`, `/availability` | Assigned members only; private notes excluded from members/guardians; minor oversight; session conflicts; report routing; no browser role activation                                         |
| `GuardianPortalService` (`domains/guardian/portal-service.ts`)       | `/api/guardian/relationships/:id`, `/consents/:scope`, `/concerns`                                                                                                    | Independently verified relationship; scope-specific/versioned consent; withdrawal removes dependent access; projection excludes restricted summaries and all private journals/notes/messages |
| `AdminService` (`domains/administration/contracts.ts`)               | `/api/admin/:collection`, `/:id`, `/transitions`, `/notes`, `/audit`, `/export`, `/views`                                                                             | Per-collection and per-command permissions; stale-version rejection; atomic bulk validation; immutable financial source records; compensating reversals; export scope and CSV escaping       |
| `AnalyticsService` (`domains/administration/analytics.tsx`)          | `/api/admin/analytics`                                                                                                                                                | Permission-scoped aggregates; explicit event cohort and denominator; unavailable metrics must not be invented                                                                                |

Mutation request bodies follow their named typed method arguments; responses use the corresponding interface return types. Production transport must add idempotency keys, CSRF protection and request IDs consistently. The generated control-by-control inventory is in INTERACTION_INVENTORY.md; routes are in PORTAL_ROUTE_INVENTORY.md.

No production API is connected. Baseline typed interfaces live in `domains/shared/contracts.ts`; the domain interfaces above extend them; demo adapters never send messages or upload files. Backend work must implement these semantics without changing presentation components.

All production endpoints: HTTPS; JSON; server validation; request correlation ID; `Cache-Control: no-store` for identity/private data. Errors: `{ code, message, fieldErrors?, requestId }`. Mutations require CSRF protection where cookie-authenticated. Do not return stack traces or raw provider errors.

| Proposed endpoint                      | Input                                                           | Successful response / invariant                                    |
| -------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| POST `/api/auth/register`              | email, password, selectedPlan?                                  | opaque pending session; no credentials in response                 |
| POST `/api/auth/login`                 | email, password                                                 | secure cookie + session profile; rate limited                      |
| POST `/api/auth/logout`                | CSRF token                                                      | revoked session                                                    |
| POST `/api/auth/recover`               | email                                                           | identical generic response regardless of existence                 |
| POST `/api/auth/reset`                 | single-use token, password                                      | token consumed; session invalidation policy                        |
| POST `/api/auth/verify`                | channel, challengeId, code                                      | verified contact; server expiry and attempt limit                  |
| POST `/api/auth/resend`                | challengeId                                                     | generic acknowledgement; server cooldown                           |
| GET `/api/session`                     | cookie                                                          | id, roles, status, permissions; never private secrets              |
| PATCH `/api/onboarding`                | versioned step payload                                          | validated draft; age classification computed server-side           |
| POST `/api/guardian/invitations`       | minimal guardian contact, relationship                          | opaque reference; queued delivery                                  |
| GET `/api/guardian/invitations/:token` | unguessable token                                               | valid/expired/used/invalid; minimise disclosed child data          |
| POST `/api/guardian/consents`          | verified guardian identity, token, versioned specific choices   | audit event; guardian authorisation checked independently          |
| DELETE `/api/guardian/consents/:id`    | guardian session                                                | revoked scope; restricted access enforced immediately              |
| POST `/api/mentor/applications`        | validated application, private file references                  | id, submitted status; no self-approval                             |
| POST `/api/uploads/intents`            | kind, mime, size                                                | expiring private upload URL; verify content and scan before review |
| POST `/api/support`                    | name, email, phone?, subject, message, consent, Turnstile token | reference; real delivery only after backend acknowledgement        |
| GET `/api/public/config`               | locale                                                          | approved categories, plans, policies, verified content             |
| POST `/api/goals`                      | title, measure, targetDate, recurringAction                     | owner-scoped initial goal                                          |

Use idempotency keys for invitations, mentor submissions, consent changes and future payments. Use optimistic concurrency/versioning for saved drafts. Retain submitted evidence only under an approved schedule. Never place a database call inside a presentation component.

Mentor review continuation: `GET /api/mentor/applications/:id` returns `{ id, status, note }` only to the applicant or an authorised reviewer; `POST /api/mentor/applications/:id/information` accepts a validated response only while more information is requested. These map to `MentorService.status` and `provideInformation`. `GuardianService.withdraw` maps to the consent deletion endpoint above. UI tests use named demo fixture IDs, never production authority.
